# Map of the system

Every page, and every function that decides something. Generated by reading the
code at `bdfc424`, not from memory.

Three surfaces sit over one shared domain core. The rule that shapes everything
below: **screens display, the domain decides.** No controller, form or table
computes a price, moves stock, or writes an order status.

## 2. The domain — where decisions are made

### Money and tax

| Function | Decides |
|---|---|
| `Money::mulDiv` | Integer rupiah arithmetic, half-up. No floats, ever |
| `Money::applyDiscountBps` | Discount in basis points |
| `Money::format` | `Rp 1.250.000` |
| `TaxCalculator::forLine` | **DPP = 11/12 × harga jual, PPN 12% of DPP** (PMK 131/2024) |
| `TaxCalculator::forStoredLines` | Sums line snapshots — never recomputes |
| `TaxCalculator::kodeTransaksi` | Coretax code `04`, not `01` |

Per line, never only on the total: summing rounded lines is not the same number
as rounding a summed total, and the faktur has to agree with the lines on it.

### Pricing — one pure function

| Function | Decides |
|---|---|
| `PriceResolver::resolve(company, sku, qty, date)` | The price **and the reason** it resolved that way |
| `PriceResolver::prime(company, skus)` | Cache hint for a batch. Same answer, fewer queries |
| `PriceResolver::forget()` | Drops the cache; the importer calls it after publishing |

Resolution order, most specific first: company SKU override → tier item →
company blanket → tier blanket → list price. Within each, the highest
`min_qty_base` the order actually reaches wins.

Cart, order confirmation, invoice and quote all call `resolve()`. **If you find
a price computed anywhere else, that is the bug.**

### Orders — every transition in one place

```
draft → submitted → confirmed → awaiting_payment → paid → shipped → completed
            ↓            ↓              ↓
        rejected     rejected        expired
```

| Function | Decides |
|---|---|
| `OrderStateMachine::submit` | Staff propose |
| `OrderStateMachine::submitAsBuyer` | Buyer proposes — recorded as a buyer, not a staff user |
| `OrderStateMachine::confirm` | **Prices snapshot, credit checked, stock reserved — one transaction** |
| `OrderStateMachine::awaitPayment` | Invoice issued + VA provisioned |
| `OrderStateMachine::markPaid` | **Webhook only** |
| `OrderStateMachine::ship` | Reservations become ledger decrements |
| `OrderStateMachine::reject` / `expire` | Releases held stock |
| `BuyerOrderPlacer::place` / `repeat` | Builds a buyer's draft and submits it |

Buyers stop at `submitted`. Confirmation is where credit and stock are decided,
and neither is a customer's call.

### Stock — append-only ledger

| Function | Decides |
|---|---|
| `StockLedger::record` | Inserts a movement; updates the cached level in the same transaction |
| `StockLedger::reserveForOrder` | **`SELECT … FOR UPDATE`** per line, ordered by SKU to avoid deadlock |
| `StockLedger::releaseForOrder` | Hands held stock back. No movement — it never left |
| `StockLedger::shipOrder` | The only place stock leaves for a sale |
| `StockLedger::available` | on hand − reserved |
| `StockLedger::reconcile` | Rebuilds the cache from the ledger. **Must always change nothing** |

Reserved at `confirmed`, decremented at `shipped`.

### Credit

| Function | Decides |
|---|---|
| `CreditChecker::check(order)` | Whether this order fits the limit |
| `CreditChecker::status(company)` | limit, outstanding, committed, available |

### Payments — append-only ledger

| Function | Decides |
|---|---|
| `PaymentLedger::recordGatewayPayment` | Money in from Xendit |
| `PaymentLedger::recordManualPayment` | Money in by transfer — **Finance and Owner only** |
| `PaymentLedger::reverse` | Inserts a reversing entry. **Never mutates a row** |
| `PaymentLedger::allocateToInvoice` | Matches money to a bill |
| `VirtualAccountProvisioner::ensureFor` | Fixed VA per company, idempotent |

Without a Xendit key, VAs are minted locally so the whole chain runs on a
laptop. A flow you cannot complete locally is one people test on production.

### Billing and numbering

| Function | Decides |
|---|---|
| `InvoiceIssuer::issueFor` | Invoice **from line snapshots only**. Idempotent |
| `DocumentNumberGenerator::nextOrderNumber` | `SO-202608-0001`, gapless |
| `DocumentNumberGenerator::nextInvoiceNumber` | `INV-202608-0001`, gapless |

Counter table under a row lock, not a Postgres sequence — sequences survive
rollback and would leave gaps.

### Cart

| Function | Decides |
|---|---|
| `CartService::forBuyer` | One basket per login |
| `CartService::add` / `setQuantity` / `remove` / `clear` | Quantities |
| `CartService::checkout` | **Locks the cart, places the order, empties it — one transaction** |
| `CartTotals::for` | Indicative figures. Read-only, stored nowhere |

**No money column exists in `carts` or `cart_items`, and none may be added.**

### Price list import

| Function | Decides |
|---|---|
| `SupplierWorkbookParser::parse` | The messy supplier workbook → rows |
| `RowClassifier::classify` | blank / header / title / data |
| `RowClassifier::titleKind` | category vs product type vs banner |
| `CellReader::splitKode` | Two SKUs in one cell → blocker |
| `CellReader::splitQtyPerCtn` | Two values, **or dimensions like `26-22-55`** → blocker |
| `PriceListImporter::parseToStaging` | Into staging. Never live prices |
| `PriceListImporter::buildDiff` | Five buckets + the safety brake |
| `PriceListImporter::publish` | New version. **Never `UPDATE`s a price** |
| `PriceListExporter::toCsv` | Export format **is** the import format |

Columns are mapped by **position**, never by header text — rows 872 and 884 of
the real file have headers that disagree with the data below them.

### Access

`Role::canSeePrices`, `canSeeCreditData`, `canCreateOrders`, `canConfirmPayment`,
`canEditOrderPrices`, `canOverrideCreditLimit`, `canPickAndShip`, `canViewAuditLog`

| Role | Can | Cannot |
|---|---|---|
| Sales | Create orders, see prices | Override credit, confirm payment |
| Warehouse | Pick, ship, print surat jalan | See prices or credit data |
| Finance | Confirm payments, manage credit + AR | Edit order line prices |
| Owner | Everything + audit log | — |

Portal resources use `ScopedToBuyer` (company-scoped base query) and
`ReadOnlyInPortal` (no generic create/edit). A test reads the schema and fails
if a portal resource over a company-owned table lacks the scope.

## 3. Background work

| Job | Trigger | Does |
|---|---|---|
| `ParsePriceListImport` | On upload | Parses the workbook into staging |
| `ProcessXenditCallback` | On webhook | Records payment, marks the order paid |
| `ReleaseStaleReservations` | Every 15 min | Frees stock on stale unpaid orders |
| `SweepStuckWebhookEvents` | Every 5 min | Recovers callbacks a dead worker claimed |

All idempotent — assume they run twice.

## 4. Data

25 models, 30 migrations. The ones that carry money or stock:

`orders` · `order_lines` (price snapshots) · `order_events` (every transition)
`invoices` · `payment_entries` (append-only) · `webhook_events` (UNIQUE gateway event id)
`stock_movements` (append-only) · `stock_levels` (cache) · `stock_reservations`
`price_list_versions` · `price_list_items` (never updated, only superseded)
`carts` · `cart_items` (**no money columns**)

## 5. Not built yet

- Faktur CSV export for Coretax — the faktur prints, but nothing writes the
  import file or reads an NSFP back
- Buyer self-service password reset
- `releaseForOrder()` has no deterministic lock ordering (`reserveForOrder` does)
- Unallocated payments don't reduce credit exposure — conservative, but wrong
- Nothing prunes abandoned carts
- Seeder ships `password` as the staff password

Launch blockers that aren't code: PSE Lingkup Privat registration, Kebijakan
Privasi page (UU PDP 27/2022), written terms of sale.
